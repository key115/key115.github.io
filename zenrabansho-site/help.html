概要 — このページの読み方

表示の見方

モニター画面の「全項目」では、監視項目ごとに次の状態を表示します。

対応可否
この Mac・OS・権限・配布の条件で取れるかどうかです。対応（取れる）・未対応（この条件では OS が値を出さない）・権限なし（未要求）（取るには追加の権限が要り、このアプリは要求していない）・権限なし（拒否）（OS が読み取りを断った。例: 他の利用者のプロセスの詳しい値）・調査中（取れるかを調べている）・対象外（取らないと決めた）。このページでは、対応以外の項に印を付けています。
取得状態
直近の取得の結果です。計測済み・計測待ち（最初の値を待っている）・再計測中（スリープや数値のリセットの後に、差分を取り直している）・取得不能（理由つき）。
鮮度
新しい・古い値（最後に取れた時刻を表示）・未観測（まだ一度も値がない）。
由来
実測（OS から読んだ値）・派生（実測から計算した値）・推定（OS などの予測）・公称（機器の仕様の値）。

画面の言葉と詳しい取得方法

画面では「使用中」「確保済み」「先読み」「ページイン」「ページアウト」など、値の意味が分かる名前を使います。% は数字に続けて表示します（例: 42.3%）。採取した割合は小数 1 桁までで、整数の余分な .0 は省きます。0 でない極小値は <0.1%（負なら >-0.1%）と示します。補間中は整数で示し、ちょうど半分の値はゼロから遠い側へ丸めます。受信と送信は別々の量です。毎秒のバイト数は通信量、公称リンク速度は接続の仕様で、同じ数値ではありません。API 名や内部の欄名などの詳しい取得方法は、この指南書の各項目の「計り方」で確認できます。

単位と数え方

  • 累積は、Mac の起動（またはその機器の数え始め）からの合計です。毎秒は、2 回の値の差を、その間の秒数で割った値です。
  • %: CPU 全体は全てのコアの合計を 100%、プロセスの CPU は 1 つのコアを使い切った時を 100% として数えます。
  • ページ: macOS がメモリを管理する単位です。大きさは「実ページサイズ」の項にあります。
  • 独自の点数（PRESS・SWAP）は、このアプリが OS の値から計算した 0〜100 の目安で、OS やアクティビティモニタの値とは一致しません。

安全のために

  • このページで勧める対処は、アクティビティモニタで確かめる・アプリを終了する・Mac を再起動する・ストレージを整理する・電源の設定を変える・電源アダプタやケーブルを確かめる、といった、利用者が安全にできる操作だけです。コマンドの入力や、システムのファイルの削除は勧めません。
  • アプリを終了する前に、作業を保存してください。強制終了では、保存していない変更が失われることがあります。
  • 名前の分からないプロセスや macOS のプロセスは終了しないでください。終了したプロセスを他のアプリやプロセスが使っていると、それらに問題が起きることがあります（Apple）。関係は、アクティビティモニタの「表示」＞「すべてのプロセス（階層表示）」で見られます。
  • 数値は目安です。困った時は、各節の参考にある Apple の記事や、このアプリのサポートをご利用ください。

よく使う道具

  • アクティビティモニタ（「アプリケーション」フォルダの「ユーティリティ」フォルダ）: どのアプリが CPU・メモリ・エネルギー・ディスク・ネットワークを使っているかを見られます。列の見出しをクリックすると並べ替えられます。
  • アプリの強制終了: アップルメニュー ＞「強制終了」、またはアクティビティモニタの「停止」ボタン。
  • システム設定: ストレージ（「一般」＞「ストレージ」）、バッテリー（「バッテリー」、デスクトップでは「エネルギー」）、アップデート（「一般」＞「ソフトウェアアップデート」）。

アプリの通信について

ヘルプや「解説」を開く時、アプリはこのページの URL をブラウザに渡すだけで、自分では通信しません。モニター画面の値は Mac の中だけで扱い、外へ送りません。なお、このページを含むこのサイトでは、ページの閲覧と App Store へのリンクのクリックを Google Analytics 4 で計測しています。

CPU 全体の使用率と内訳

ID: cpu.total.busy CPU 全体の使用率 ・ cpu.total.user CPU全体 · 利用者の処理 ・ cpu.total.system CPU全体 · システムの処理 ・ cpu.total.nice CPU全体 · 優先度を下げた処理 ・ cpu.total.idle CPU全体 · 未使用

意味
Mac 全体で CPU がどれだけ働いているかの割合です。busy は働いていた割合で、user・system・nice の合計（＝100% − idle）。user はアプリなど利用者側の処理、system は macOS の中心部（カーネル）がアプリに代わって行う処理（ファイルの読み書きや通信など）、nice は優先度を下げて動いている処理、idle は何もしていなかった割合です。アクティビティモニタの「CPU」タブの下にある「システム」「ユーザ」「アイドル状態」に相当します（数え方が完全に同じとは限りません）。
単位
%（全てのコアの時間の合計を 100% とする）
計り方
macOS の CPU の時間の積算（host_statistics の HOST_CPU_LOAD_INFO）を約 1 秒ごとに読み、前回との差から割合を出します。
高い時に考えられること
アプリが重い処理（動画の書き出し・プログラムのビルド・ゲーム・たくさんのブラウザのタブなど）をしている時に高くなります。system だけが高い時は、大量のファイルの読み書きや通信など、OS の中の処理が多い状態です。Apple によると、データの移行の後の Spotlight の索引作成などでも負荷が上がります。
対処
  • アクティビティモニタ（「アプリケーション」フォルダの「ユーティリティ」フォルダ）の「CPU」タブで「% CPU」の列の見出しをクリックして並べ替え、CPU を多く使っているアプリを確かめます。
  • 使っていないアプリを終了します（作業は先に保存）。応答しないアプリは、アップルメニュー ＞「強制終了」か、アクティビティモニタの「停止」ボタン ＞「強制終了」で終了します。強制終了では保存していない変更が失われることがあります。名前の分からないプロセスや macOS のプロセスは終了しないでください。終了したプロセスを他のアプリやプロセスが使っていると、それらに問題が起きることがあります（Apple）。関係は、アクティビティモニタの「表示」＞「すべてのプロセス（階層表示）」で見られます。
  • 別の Mac からデータを移した後などは、Spotlight の索引作成でしばらく高くなることがあるので、終わるまで待ちます（Apple のファンの記事）。
  • 長く続く時は Mac を再起動し、アプリと macOS を最新にします（システム設定 ＞「一般」＞「ソフトウェアアップデート」）。
注意
短い間だけ 100% 近くになるのは普通です。長く続き、操作が重い・ファンが回る・電池の減りが速い時に確かめれば十分です。

コアごとの使用率・コア別履歴・最大コア使用率

ID: cpu.core.busy コアの使用率 ・ cpu.core.user コア · 利用者の処理 ・ cpu.core.system コア · システムの処理 ・ cpu.core.nice コア · 優先度を下げた処理 ・ cpu.core.idle コア · 未使用 ・ cpu.core.history コア別履歴 ・ cpu.core.maximum 最大コア使用率

意味
コアごとの使用率と、その内訳（busy・user・system・nice・idle）、直近の推移です。最大コア使用率は、一番忙しいコアの使用率です。
単位
%（そのコアの時間を 100% とする）
計り方
コアごとの CPU の時間（host_processor_info の PROCESSOR_CPU_LOAD_INFO）の差分から出します。最大コア使用率は、全てのコアの値が同じ区間でそろった時だけ出します。
高い時に考えられること
1 つのコアだけが 100% 近くで全体は低い時は、1 つの処理が 1 つのコアを使い続けています（並列にできない処理や、1 つのアプリ・タブの重い処理）。全てのコアが高い時は、並列に動く重い処理をしています。Apple シリコンの Mac には高性能（P）コアと高効率（E）コアがあり、OS が処理を振り分けるので、片方だけが高いこともあります。
対処
  • アクティビティモニタ（「アプリケーション」フォルダの「ユーティリティ」フォルダ）の「CPU」タブで「% CPU」の列の見出しをクリックして並べ替え、CPU を多く使っているアプリを確かめます。
  • 使っていないアプリを終了します（作業は先に保存）。応答しないアプリは、アップルメニュー ＞「強制終了」か、アクティビティモニタの「停止」ボタン ＞「強制終了」で終了します。強制終了では保存していない変更が失われることがあります。名前の分からないプロセスや macOS のプロセスは終了しないでください。終了したプロセスを他のアプリやプロセスが使っていると、それらに問題が起きることがあります（Apple）。関係は、アクティビティモニタの「表示」＞「すべてのプロセス（階層表示）」で見られます。
  • 別の Mac からデータを移した後などは、Spotlight の索引作成でしばらく高くなることがあるので、終わるまで待ちます（Apple のファンの記事）。
  • 長く続く時は Mac を再起動し、アプリと macOS を最新にします（システム設定 ＞「一般」＞「ソフトウェアアップデート」）。

コアの分類（P コア・E コア）

ID: cpu.core.kind コアの分類 ・ cpu.configuration.performance P コア数 ・ cpu.configuration.efficiency E コア数

意味
各コアが高性能（P）コアか高効率（E）コアかと、それぞれの数です。値に良し悪しはありません。
計り方
sysctl の hw.perflevel* の値と、機器の情報（IODeviceTree）・コアの数を照合し、確かめられた構成の時だけ分類します。確かめられない時は「分類不明」と表示します。

CPU の構成（名前・コアの数）

ID: cpu.configuration.name CPU / SoC ・ cpu.configuration.logical 論理コア数（最大） ・ cpu.configuration.physical 物理コア数（最大） ・ cpu.configuration.active 有効コア数

意味
CPU（Apple シリコンでは SoC）の名前、論理コア数（OS が同時に処理を割り当てられる数）、物理コア数（部品としてのコアの数）、有効コア数（いま使えるコアの数）です。値に良し悪しはありません。
計り方
sysctl の machdep.cpu.brand_string・hw.logicalcpu_max・hw.physicalcpu_max・hw.activecpu を、最初に必要になった時に一度だけ読みます。
注意
同時マルチスレッディング（Intel の Hyper-Threading）のある Mac では、論理コア数が物理コア数より多くなります。

負荷平均（1 分・5 分・15 分）

ID: cpu.load.avg1 負荷平均 1分 ・ cpu.load.avg5 負荷平均 5分 ・ cpu.load.avg15 負荷平均 15分

意味
直近 1 分・5 分・15 分の「負荷平均」です。CPU で実行中か、実行の順番を待っている処理の数の平均で、CPU 使用率（%）とは別の値です。
単位
処理の数
計り方
getloadavg で読みます。
高い時に考えられること
論理コア数より大きい状態が続く時は、CPU の順番待ちが起きていて、操作が重く感じることがあります。1 分の値だけが高く 15 分の値が低い時は、最近始まった一時的な負荷です。
対処

  • 別の Mac からデータを移した後などは、Spotlight の索引作成でしばらく高くなることがあるので、終わるまで待ちます（Apple のファンの記事）。

注意
目安の値です。コアの数が多い Mac ほど、大きな値でも余裕があります。

全体のプロセス数

ID: cpu.system.tasks プロセス数（全体）

意味
Mac 全体に存在するプロセスの数です。アプリだけでなく、macOS やバックグラウンドの処理も含みます。プロセス表に表示できた行数とは別の値です。
単位
プロセスの数（件・瞬時値・分母なし）
計り方
CPU のページが見えている間、約 1 秒ごとにカーネルの全体の件数（processor_set_default → processor_set_statistics の PROCESSOR_SET_LOAD_INFO、task_count）を読みます。表の行数を数えているのではありません。
高い時に考えられること
多くのアプリや、その補助のプロセス・バックグラウンドの処理が動いていることがあります。数が多いだけでは、CPU を多く使っている、または異常があるとは判断できません。
対処
  • 動作が重い時は、アクティビティモニタ（「アプリケーション」フォルダの「ユーティリティ」フォルダ）の「CPU」タブで「% CPU」の列を並べ替え、CPU を多く使っているアプリを確かめます。全体のプロセス数・スレッド数はタブの下に表示されます。
  • 使っていないアプリを終了します（作業は先に保存）。応答しないアプリは、アップルメニュー ＞「強制終了」か、アクティビティモニタの「停止」ボタン ＞「強制終了」で終了します。強制終了では保存していない変更が失われることがあります。名前の分からないプロセスや macOS のプロセスは終了しないでください。終了したプロセスを他のアプリやプロセスが使っていると、それらに問題が起きることがあります（Apple）。関係は、アクティビティモニタの「表示」＞「すべてのプロセス（階層表示）」で見られます。
注意
アクティビティモニタとは更新の時刻や数え方が異なることがあり、同じ数になるとは限りません。取得できない時は理由を表示し、0 で埋めません。

全体のスレッド数

ID: cpu.system.threads スレッド数（全体）

意味
Mac 全体のスレッドの数です。スレッドはプロセスの中で処理を進める実行単位で、1 つのプロセスに複数あることがあります。kernel_task のスレッドも含みます。
単位
スレッドの数（本・瞬時値・分母なし）
計り方
CPU のページが見えている間、約 1 秒ごとに processor_set_statistics の PROCESSOR_SET_LOAD_INFO、thread_count を読みます。取得できたプロセス表のスレッド数を足した値ではありません。
高い時に考えられること
複数の処理を並行して進めるアプリや、バックグラウンドの処理が多いことがあります。待機中のスレッドもあるので、数が多いことと CPU 使用率が高いことは同じではありません。
対処
  • 動作が重い、または数が増え続ける時は、アクティビティモニタ（「アプリケーション」フォルダの「ユーティリティ」フォルダ）で CPU やメモリを多く使うアプリを確かめます。「表示」＞「列」で表示する列を選び、プロセスを選んで情報を見ることもできます。
  • 使っていないアプリを終了します（作業は先に保存）。応答しないアプリは、アップルメニュー ＞「強制終了」か、アクティビティモニタの「停止」ボタン ＞「強制終了」で終了します。強制終了では保存していない変更が失われることがあります。名前の分からないプロセスや macOS のプロセスは終了しないでください。終了したプロセスを他のアプリやプロセスが使っていると、それらに問題が起きることがあります（Apple）。関係は、アクティビティモニタの「表示」＞「すべてのプロセス（階層表示）」で見られます。
注意
CPU のコア数・実行待ちの数・起動後の累計ではありません。kernel_task を含む全体値なので、プロセス表の合計や別の時刻のアクティビティモニタの値とは一致しないことがあります。

CPU の公称周波数（P/E クラスターは最大）

ID: cpu.frequency.nominal CPU 公称周波数（クラスターは最大）

意味
CPU の構成を表す公称の周波数です。Apple シリコンでは P コア・E コアのクラスターごとに「公称（最大）」を表示します。現在周波数や現在の CPU 使用率ではありません。
単位
原値は Hz（1 秒あたりの回数）。CPU のページでは GHz（10 億 Hz）で表示します。
計り方
最初に CPU の採取が必要になった時に読み、成功値と、取得元・鍵が無いことや表の形式が合わないことを確認した結果を保持します。列挙の開始に失敗した時や途中で無効になった時だけ、次回に再試行します。Apple シリコンでは IORegistry の pmgr にある電圧・周波数の表の最大値（P: voltage-states5-sram、E: voltage-states1-sram）です。Intel では既存の sysctl hw.cpufrequency を公称値として読みます。
高い時に考えられること
構成の表に大きな周波数が記録されていることを示します。今その周波数で動いている、または CPU の負荷が高い、という意味ではありません。この値だけで Mac 同士の性能や故障を判断することもできません。
対処
  • この構成値を下げる対処は不要です。動作が重い時は、アクティビティモニタ（「アプリケーション」フォルダの「ユーティリティ」フォルダ）の「CPU」タブで CPU を多く使うアプリを確かめます。

注意
Apple シリコンの値は、Apple が公表した仕様値ではなく、文書の無い IORegistry の鍵から読んだ観測値です。M1 のみ実測済みで、M2 以降・Intel は未検証です。最大値が 500 MHz 以上の Hz の値だけを受け入れます。M4 以降の kHz 形式は実機未検証のため換算せず、範囲外として値を表示しません。M4 の単位と表は別途実機照合が必要です。走査を正常に終えて pmgr や鍵が無い時、または表の長さ・値の範囲が合わない時は、未対応として結果を保持し、毎秒読み直しません。0 や別のクラスターの値で埋めません。列挙の開始失敗・途中の無効化は取得不能とし、次回に再試行します。現在周波数は別の未対応項目です。

メモリ

メモリ（RAM）は、アプリがいま使っているデータを置く場所です。足りなくなると、macOS は使われていないデータを圧縮したり、ストレージへ書き出したり（スワップ）して空きを作ります。Apple は、メモリが足りているかをアクティビティモニタの「メモリプレッシャー」で判断するよう案内しています。空き（free）が少ないこと自体は問題ではありません。

  • タブの下の「メモリプレッシャー」のグラフの色は、Apple の説明では、緑＝RAM を効率よく使えている・黄＝今後 RAM が不足するおそれ・赤＝RAM の増設が必要な状態です。赤が続く時は、同時に使うアプリを減らします。増設できる Mac かどうかは Apple の記事「アクティビティモニタでMacに追加のRAMが必要かどうかを確認する」で確かめられます。
注意

意味

単位

計り方

意味

単位

計り方

有線のリンク速度（公称）

ID: net.if.linkSpeed リンク速度

意味
有線インターフェイスが報告する公称のリンク速度です。実際に送受信した量や、インターネットの実効速度を計った値ではありません。
単位
Mb/s（Mbps、毎秒 100 万ビット）。丸めて 1000 Mb/s 以上になる値は Gb/s で表示します（1 Gb/s＝1000 Mb/s）。バイト/秒とは異なります（1 バイト＝8 ビット）。小さな非 0 の値は「< 0.01 Mb/s」のように表示し、0 に丸めません。
計り方
macOS の IFMIB が報告するインターフェイスごとの bit/s を Mb/s に換算します。経路とは独立した装置一覧（SystemConfiguration）で有線と確認でき、リンクが有効な接続だけを対象にします。DHCP の失敗などで通信経路が無くても取得します。
高い時に考えられること
公称の接続速度が高いことを示します。大量に通信している、混雑している、という意味ではありません。高い値だけで対処する必要はありません。
低い時に考えられること
想定より低い場合は、ケーブル・アダプタ・接続先ポートの対応速度や接続状態を確認します。
対処
  • 想定する速度に対応したケーブル・アダプタ・ポートかどうかと、接続が緩んでいないかを確認します。
  • 実際の通信も遅い時は、アクティビティモニタ（「アプリケーション」フォルダの「ユーティリティ」フォルダ）の「ネットワーク」タブで通信量の多いアプリを確認します。不要なアプリを終了する場合は、次の注意に従ってください。
  • 使っていないアプリを終了します（作業は先に保存）。応答しないアプリは、アップルメニュー ＞「強制終了」か、アクティビティモニタの「停止」ボタン ＞「強制終了」で終了します。強制終了では保存していない変更が失われることがあります。名前の分からないプロセスや macOS のプロセスは終了しないでください。終了したプロセスを他のアプリやプロセスが使っていると、それらに問題が起きることがあります（Apple）。関係は、アクティビティモニタの「表示」＞「すべてのプロセス（階層表示）」で見られます。
注意
Wi-Fi など有線でない接続と OS の値が 0 の場合は未対応、10 Tbps（10000 Gb/s）を超える値は取得不能です。種別やリンク状態が一時的に分からない時は取得不能とし、以前の値があれば古い値として残します。リンクが無効なら速度を消して接続を待ち、0 や別の速度で埋めません。Apple は、管理者から特別な指示がない限り、ネットワークのハードウェア設定を自動設定のまま使うよう案内しています。

CPU 使用率（1 コア基準）

ID: proc.cpu.usage CPU使用率（1コア基準）

意味
そのプロセスが CPU を使っている割合です。1 つのコアを使い切った時を 100% とするので、複数のコアを使うプロセスは 100% を超えます。
単位
%（1 コア＝100%）
計り方
プロセスの CPU の時間（PROC_PIDTASKINFO）の差分を、スリープ中は進まない時計の経過時間で割ります。区間は 250 ミリ秒以上です。
高い時に考えられること
そのアプリが重い処理をしています。処理が終わっているはずなのに高いまま続く時は、アプリが応答しない、または同じ処理を繰り返している可能性があります。
対処
  • 作業中なら終わるのを待ちます。
  • 使っていないアプリを終了します（作業は先に保存）。応答しないアプリは、アップルメニュー ＞「強制終了」か、アクティビティモニタの「停止」ボタン ＞「強制終了」で終了します。強制終了では保存していない変更が失われることがあります。名前の分からないプロセスや macOS のプロセスは終了しないでください。終了したプロセスを他のアプリやプロセスが使っていると、それらに問題が起きることがあります（Apple）。関係は、アクティビティモニタの「表示」＞「すべてのプロセス（階層表示）」で見られます。
  • 繰り返す時は、そのアプリのアップデートを確かめます（Apple の記事「Macでアプリがフリーズまたは突然終了する場合」）。

CPU 時間・観測窓・経過

ID: proc.cpu.time CPU時間 ・ proc.cpu.userTime アプリの CPU 時間累積 ・ proc.cpu.systemTime システムの CPU 時間累積 ・ proc.cpu.interval CPU観測窓 ・ proc.task.elapsed プロセス経過

意味
プロセスが起動してから使った CPU の時間の合計（user＝自分の処理、system＝OS の中心部が代わりにした処理）、使用率を計った区間の長さ（CPU 観測窓）、プロセスが起動してからの経過時間です。
単位
秒
計り方
PROC_PIDTASKINFO と PROC_PIDTBSDINFO で読みます。
注意
長く動いているプロセスほど CPU 時間は大きくなります。いまの重さを比べる時は CPU 使用率を見てください。

その他（システム・他ユーザー）CPU

ID: proc.cpu.other その他（システム・他ユーザー）CPU

意味
Mac 全体の CPU の使用のうち、一覧に詳しく出ないプロセス（macOS のシステムや他の利用者のプロセス）の分です。
単位
%（1 コア＝100%）
計り方
全体の CPU 使用率 × 論理コア数 × 100% から、一覧で読めたプロセスの合計を引きます（派生の値）。区間がそろわない時は出しません。
高い時に考えられること
システムや他の利用者のプロセスが CPU を使っています。データの移行の後の索引作成、写真の解析、バックアップなどが考えられます。
対処
アクティビティモニタは全てのプロセスを表示できます（「表示」＞「すべてのプロセス」）。そこで確かめ、作業が終わるのを待ちます。長く続く時は Mac を再起動します。

プロセスのメモリ（RSS・物理 RAM 比・Virtual size・Pageins）

ID: proc.task.rss メモリ ・ proc.task.memoryPercent メモリ（物理 RAM 比） ・ proc.task.virtual 仮想メモリ ・ proc.task.pageins ページイン

意味
RSS（常駐サイズ）＝そのプロセスがいま実メモリに置いている量（他のプロセスと共有している分も含む）。メモリ（物理 RAM 比）＝RSS ÷ 搭載メモリ。Virtual size＝そのプロセスが確保したアドレスの広さで、実メモリの使用量ではありません。Pageins＝そのプロセスがストレージから読み込んだページの数です。
単位
バイト・%・ページ
計り方
PROC_PIDTASKINFO で読みます。物理 RAM 比の分母は hw.memsize です。
高い時に考えられること
RSS が大きいアプリは、メモリを多く使っています。メモリの圧迫が高い時に減らす候補です。
対処
使っていないアプリなら終了します。ブラウザなら使っていないタブを閉じます。
注意
共有分を含むため、全てのプロセスの RSS の合計は搭載メモリより大きくなることがあります。アクティビティモニタの「メモリ」の列とは計り方が違い、値は一致しません。Virtual size が大きいのは普通です。

プロセスの名前・所有者・PID・開始時刻・スレッド数・状態

ID: proc.identity.name プロセス名 ・ proc.identity.owner 所有者 ・ proc.identity.pid PID ・ proc.identity.startTime 開始時刻 ・ proc.task.threads スレッド数 ・ proc.task.state プロセス状態

意味
プロセスの名前、所有者（どの利用者のプロセスか）、PID（プロセスの番号。終わると別のプロセスに使い回されます）、開始時刻、スレッド数（プロセスの中で同時に進む処理の数）、状態（実行中・待機中・終了など）です。値に良し悪しはありません。
計り方
KERN_PROC_ALL でプロセスを数え、PROC_PIDTBSDINFO と PROC_PIDTASKINFO で読みます。
注意
プロセスの名前などは書き出しでは伏せます。

親プロセス

ID: proc.identity.parentPID 親プロセスの PID

意味
選んだプロセスの親の番号（PID）です。親が一覧にあれば、名前も出します。親があなたのプロセスなら、その行へ移動できます。
単位
番号（count）。使用率ではなく、大小に良し悪しはありません。
計り方
既存の KERN_PROC_ALL の kp_eproc.e_ppid を読み、同じ子の親 PID が2回の一覧の読み取りで一致することを確かめます。途中で変わった時は、その回だけ「親は終了済み（不明）」にします。開始時刻の前後では判定しません。
対処
負荷の大きいプロセスがどの処理に属するかを調べる手がかりにします。アクティビティモニタの「表示」＞「すべてのプロセス（階層表示）」でも関係を確かめられます。
注意
一覧に親がいない時（読み取りの間に終了・保持上限など）と親 PID が 0 の時は不明です。名前を推測しません。親 PID と名前は診断の要約で既定の伏せ字対象です。名前の分からないプロセスや macOS のプロセスを終了しないでください。

エネルギー影響・GPU・クラッシュ・ハング・アプリ名・通信量・FD 数・QoS

電池残量

ID: power.battery.chargeRatio 電池残量

意味
電池の残りの量です。
単位
%
計り方
macOS の電源の情報（IOPowerSources）の「現在容量 ÷ 満充電容量」です。
低い時・減りが速い時に考えられること
画面の明るさ、重い処理、GPU を使うアプリ、たくさんのブラウザのタブなどで、電池の減りが速くなります。

電源の種類・AC 接続・充電中・充電完了・電池の搭載

ID: power.source.kind 電源種別 ・ power.source.ac AC接続 ・ power.battery.charging 充電中 ・ power.battery.charged 充電完了 ・ power.battery.present 内蔵電池の搭載

意味
いまの電源（AC 電源・電池・UPS）、電源アダプタがつながっているか、充電中か、充電が終わったか、内蔵の電池があるかです。
計り方
macOS の電源の情報（IOPowerSources）で読みます。
電源につないでも充電中にならない時に考えられること
「バッテリー充電の最適化」や充電上限で充電を止めている（バッテリーのメニューに「充電保留中」などと表示）、電源アダプタのワット数が足りない、ケーブルがデータ転送専用、電源アダプタが熱くなって止まっている、などです（Apple の記事）。
対処
バッテリーのメニューで状態を確かめ、すぐに満充電が要る時は「今すぐフル充電」を選びます。付属のものと同じかそれ以上のワット数の電源アダプタと、充電に使えるケーブルを使います。電源アダプタをコンセントから抜いて数秒待ってから差し直し、Mac を再起動します（Apple の記事「USB-C電源アダプタでMacノートブックが充電されない場合」）。
注意
「電源接続・非充電」は故障とは限りません。

電池の容量と健全度

ID: power.battery.currentCapacity 現在容量 ・ power.battery.maxCapacity 満充電容量 ・ power.battery.designCapacity 設計容量 ・ power.battery.health 電池の健全度（条件付き）

意味
現在容量、満充電容量（いまの電池がためられる量）、設計容量（新品の時の量）と、健全度（電池の詳しい情報にある満充電の容量 ÷ 設計容量の目安）です。
単位
現在容量と満充電容量は OS の相対の単位（mAh とは限りません）、設計容量は電池の情報の単位、健全度は %
計り方
現在容量と満充電容量は IOPowerSources、設計容量と健全度は電池の詳しい情報（AppleSmartBattery。Apple が文書にしていない値）で読みます。値がない Mac もあります。
低い時に考えられること
電池は使うにつれて少しずつ劣化し、ためられる量が減ります。
対処
電池の状態は、システム設定 ＞「バッテリー」の「バッテリーの状態」で確かめます。「修理サービス推奨」と表示された時は Apple の案内に従います（そのまま使っても安全で、不便を感じる時は修理サービスを利用できます）。
注意
Apple は、他社のアプリが表示する電池の状態は正確でないことがあるとし、macOS が表示する情報を参考にするよう案内しています。この値は目安として使ってください。

充放電回数

ID: power.battery.cycles 充放電回数

意味
電池の充放電回数です。電池の電力を全部使い切った分で 1 回と数えるので、充電した回数とは一致しません（Apple）。
単位
回
計り方
電池の詳しい情報（AppleSmartBattery）で読みます。
多い時に考えられること
Apple は機種ごとに最大の充放電回数を示しています。最大に達すると電池は消耗したとみなされ、交換が推奨されます。使い続けることはできますが、使える時間は短くなります。
対処
機種ごとの最大の回数は Apple の記事「Macノートブックのバッテリーの充放電回数を調べる」で確かめます。option キーを押しながらアップルメニュー ＞「システム情報」＞「電源」でも回数を確かめられます。「バッテリー充電の最適化」をオンにすると劣化を抑えられます（Apple）。

システムの消費電力

ID: power.system.loadWatts システムの消費電力（W）

意味
OS が報告するシステムの消費電力です。CPU だけの電力ではありません。
単位
W（ワット）
計り方
IORegistryEntryCreateCFProperty で AppleSmartBattery の PowerTelemetryData.SystemLoad を読み、mW ÷ 1,000 で W に換算します。
高い時に考えられること
作業量・充電・接続するアダプターにより値が変わります。CPU だけの使用量や、故障の有無を示す値ではありません。
対処
  • アクティビティモニタ（「アプリケーション」フォルダの「ユーティリティ」フォルダ）の「エネルギー」タブで、エネルギー消費の大きいアプリを確かめます。
  • 必要のないアプリは、作業を保存してから通常の方法で終了します。名前の分からないプロセスや macOS のプロセスは終了しないでください。
注意
OS が数十秒ごとに更新する値を、表示中は約60秒ごとに読みます。表示の時刻は取得時刻で、毎秒の測定ではありません。電源の切り替え直後は計測待ちにし、約40秒後に読み直します。取得元の辞書の鍵・単位・符号は公開文書がなく、機種・OS により値が欠けます。電池のない Mac は未対応です。電池駆動時の符号と値の意味は実機での照合が済んでいません。符号だけで充電・放電の向きを判断せず、入力と電池の値を合算して全体の電力を作らないでください。

アダプターからの入力電力・電圧・電流

ID: power.system.inputWatts アダプターからの入力（W） ・ power.system.inputVolts アダプターからの入力（V） ・ power.system.inputAmperes アダプターからの入力（A）

意味
OS が報告するアダプターからの入力です。アダプターの公称仕様や、コンセントでの消費電力とは別の値です。
単位
電力は W、電圧は V、電流は A
計り方
IORegistryEntryCreateCFProperty で AppleSmartBattery の PowerTelemetryData を読みます。SystemPowerIn（mW）・SystemVoltageIn（mV）・SystemCurrentIn（mA）をそれぞれ 1,000 で割り、W・V・A に換算します。
高い時に考えられること
作業量・充電・接続するアダプターにより値が変わります。CPU だけの使用量や、故障の有無を示す値ではありません。
低い時に考えられること
入力が低いだけで故障とは判断できません。作業量や充電の状態、接続するアダプターと合わせて読みます。
対処
  • アクティビティモニタ（「アプリケーション」フォルダの「ユーティリティ」フォルダ）の「エネルギー」タブで、エネルギー消費の大きいアプリを確かめます。

計り方

対処
机のような硬く平らな場所に置き、通気口をふさがないようにします。CPU や GPU を多く使っているアプリ（アクティビティモニタで確かめる）を終了するか、重い作業を止めます。周りの温度が低い場所で使います。低電力モードを使うと、一部の機種ではファンの音も減らせます。負荷が低いのにファンが回り続ける時は、Apple の記事「Apple製品のファンとその動作音について」の機種ごとの手順に従います。

「熱の状態」（ProcessInfo.thermalState の4段階）とは別の指標です。温度の実測や安全の保証として使わないでください。実機では段階0の取得を確認していますが、段階1〜4の負荷時の照合は済んでいません。
