Overview — How to read this guide

Reading the status

All Metrics in the Monitor window shows the following for each metric.

Support
Whether the metric can be read on this Mac, OS, permissions and distribution. Supported, Unsupported (macOS doesn't provide it in these conditions), Permission required (not requested) (it needs an additional permission this app doesn't request), Permission denied (macOS refused access, for example to details of other users' processes), Under investigation, and Excluded (we decided not to collect it). This page marks every entry that isn't supported.
Acquisition
The result of the latest reading: Measured, Waiting for sample (waiting for the first value), Rebaselining (restarting a rate after sleep or a counter reset) and Unavailable (with a reason).
Freshness
Fresh, Stale (shows when it was last read) and Unobserved (no value yet).
Provenance
Measured (read from macOS), Derived (calculated from measured values), Estimated (a prediction, for example by macOS) and Nominal (a device specification).

Screen labels and collection details

Screen labels describe the measurements: Active, Wired, Speculative, Page-ins and Page-outs. Percentages follow the number without a space (for example, 42.3%). Sampled percentages use up to one decimal place, omitting an unnecessary .0. Tiny nonzero values appear as <0.1% (or >-0.1% when negative). Interpolated values use whole numbers, with exact ties rounded away from zero. Received and sent traffic are separate quantities. Bytes per second measures traffic; nominal link speed describes the connection specification. This guide’s measurement descriptions include API names and internal field names. In the app, these details are available in the developer section of the All Metrics inspector.

Units and counting

  • Cumulative values are totals since your Mac started (or since the device began counting). Per-second values are the difference between two readings divided by the seconds between them.
  • %: total CPU treats all cores together as 100%; process CPU treats one fully used core as 100%.
  • Pages: the unit macOS uses to manage memory. See Actual page size for its size.
  • App scores (PRESS and SWAP) are 0–100 guides this app calculates from macOS values; they won't match values in macOS or Activity Monitor.

Staying safe

  • This guide only suggests actions you can take safely: checking Activity Monitor, quitting apps, restarting your Mac, freeing up storage, changing power settings, and checking your power adapter and cables. It never suggests typing commands or deleting system files.
  • Save your work before quitting an app. Force quitting can lose unsaved changes.
  • Don't quit processes you don't recognize or processes that belong to macOS: if other apps or processes are using a process you quit, they can have problems (Apple). To see how processes are related, choose View > All Processes, Hierarchically in Activity Monitor.
  • Values are a guide. If you need help, see Apple's articles listed in each section, or contact this app's support.

Tools you'll use

  • Activity Monitor (in the Utilities folder inside Applications): shows which apps use CPU, memory, energy, disk and network. Click a column heading to sort.
  • Force quitting an app: Apple menu > Force Quit, or the Stop button in Activity Monitor.
  • System Settings: storage (General > Storage), battery (Battery, or Energy on desktop Macs) and updates (General > Software Update).

About network access

When you open Help or Learn More, the app only hands this page's URL to your browser and doesn't connect to the network itself. Values in the Monitor stay on your Mac and are never sent anywhere.

CPU

The CPU is the part that does the computing. A Mac's CPU has several cores, and each core can work on a different task at the same time.

Total CPU usage and breakdown

ID: cpu.total.busy Total CPU usage · cpu.total.user Total CPU user · cpu.total.system Total CPU system · cpu.total.nice Total CPU nice · cpu.total.idle Total CPU idle

Meaning
How busy the CPU is across the whole Mac. busy is the share of time spent working: user + system + nice (= 100% − idle). user is work done by apps and other user-side code, system is work done by the core of macOS (the kernel) on behalf of apps, such as reading files or networking, nice is work running at a lowered priority, and idle is time spent doing nothing. These correspond to System, User and Idle at the bottom of Activity Monitor's CPU tab (the counting may not be exactly the same).
Unit
% (the time of all cores together is 100%)
How it's measured
Reads the CPU time counters of macOS (host_statistics, HOST_CPU_LOAD_INFO) about once a second and computes the share from the difference since the last reading.
When it's high
Apps doing heavy work (exporting video, building software, games, many browser tabs) push it up. If only system is high, the OS itself is doing a lot of work, such as heavy file reading/writing or networking. Apple notes that work such as Spotlight indexing after a data migration also raises the load.
What you can do
  • Open Activity Monitor (in the Utilities folder inside Applications), click the CPU tab and sort by the % CPU column to find the apps using the most CPU.
  • Quit apps you aren't using (save your work first). If an app doesn't respond, choose Apple menu > Force Quit, or click the Stop button in Activity Monitor and choose Force Quit. Force quitting can lose unsaved changes. Don't quit processes you don't recognize or processes that belong to macOS: if other apps or processes are using a process you quit, they can have problems (Apple). To see how processes are related, choose View > All Processes, Hierarchically in Activity Monitor.
  • After migrating data from another Mac, for example, Spotlight indexing can keep it high for a while; let it finish (Apple's article on fans).
  • If it stays high, restart your Mac and update your apps and macOS (System Settings > General > Software Update).
Note
Short spikes near 100% are normal. Look into it only when it stays high and your Mac feels slow, the fans spin up, or the battery drains quickly.

Per-core usage, per-core history and busiest core

ID: cpu.core.busy Core usage · cpu.core.user Core user · cpu.core.system Core system · cpu.core.nice Core nice · cpu.core.idle Core idle · cpu.core.history Per-core history · cpu.core.maximum Busiest core usage

Meaning
Usage of each core with its breakdown (busy, user, system, nice, idle) and its recent history. Busiest core usage is the usage of the busiest core.
Unit
% (the time of that core is 100%)
How it's measured
Computed from the difference in each core's CPU time (host_processor_info, PROCESSOR_CPU_LOAD_INFO). The busiest core is shown only when all cores were measured over the same interval.
When it's high
If one core is near 100% while the total is low, a single task keeps one core busy (work that can't run in parallel, or one heavy app or tab). If all cores are high, something heavy is running in parallel. Macs with Apple silicon have performance (P) and efficiency (E) cores, and macOS assigns work between them, so one kind can be busier than the other.

To see how processes are related, choose View > All Processes, Hierarchically in Activity Monitor.

  • If it stays high, restart your Mac and update your apps and macOS (System Settings > General > Software Update).

Core classification (P and E cores)

ID: cpu.core.kind Core classification · cpu.configuration.performance P cores · cpu.configuration.efficiency E cores

Meaning
Whether each core is a performance (P) core or an efficiency (E) core, and how many of each there are. There is no good or bad value.
How it's measured
Cross-checks sysctl hw.perflevel* with the device tree (IODeviceTree) and the core counts, and classifies only when the layout is confirmed. Otherwise the core shows as unclassified.

CPU configuration (name and core counts)

ID: cpu.configuration.name CPU / SoC · cpu.configuration.logical Logical cores (maximum) · cpu.configuration.physical Physical cores (maximum) · cpu.configuration.active Active cores

Meaning
The name of the CPU (the SoC on Apple silicon), the logical core count (how many tasks macOS can schedule at once), the physical core count (the cores as hardware) and the active core count (cores available now). There is no good or bad value.
How it's measured
Reads sysctl machdep.cpu.brand_string, hw.logicalcpu_max, hw.physicalcpu_max and hw.activecpu once, the first time they're needed.
Note
On Macs with simultaneous multithreading (Intel Hyper-Threading), the logical core count is larger than the physical core count.

Load average (1, 5 and 15 minutes)

ID: cpu.load.avg1 Load average 1 minute · cpu.load.avg5 Load average 5 minutes · cpu.load.avg15 Load average 15 minutes

Meaning
The load average over the last 1, 5 and 15 minutes: the average number of tasks running on the CPU or waiting for their turn. It's a different value from CPU usage (%).
Unit
Number of tasks
How it's measured

When it's high
If it stays above the logical core count, tasks are waiting for the CPU and your Mac can feel slow. If only the 1-minute value is high and the 15-minute value is low, the load started recently and is temporary.

Use it as a rough guide. The more cores a Mac has, the higher the value it can handle.

System-wide process count

ID: cpu.system.tasks Processes (system total)

Meaning
The number of processes across the whole Mac, including macOS and background work as well as apps. It differs from the number of rows available in the process table.
Unit
Number of processes (instantaneous count, no denominator)
How it's measured
While the CPU page is visible, reads the kernel's system-wide count about once a second: processor_set_default → processor_set_statistics, PROCESSOR_SET_LOAD_INFO, task_count. It does not count process-table rows.
When it's high
Many apps, helper processes or background tasks may be running. A high count alone does not show high CPU usage or a problem.
What you can do
  • If your Mac feels slow, open Activity Monitor (in the Utilities folder inside Applications), click CPU and sort by the % CPU column to find apps using the most CPU. The system process and thread counts appear below the list.
  • Quit apps you aren't using (save your work first). If an app doesn't respond, choose Apple menu > Force Quit, or click the Stop button in Activity Monitor and choose Force Quit. Force quitting can lose unsaved changes. Don't quit processes you don't recognize or processes that belong to macOS: if other apps or processes are using a process you quit, they can have problems (Apple). To see how processes are related, choose View > All Processes, Hierarchically in Activity Monitor.
Note
Activity Monitor can use different update times or counting rules, so the counts may differ. If the value cannot be read, the app shows a reason instead of filling in zero.

System-wide thread count

ID: cpu.system.threads Threads (system total)

Meaning
The number of threads across the whole Mac. A thread is a unit of execution within a process, and one process can have several threads. Includes kernel_task threads.
Unit
Number of threads (instantaneous count, no denominator)
How it's measured
While the CPU page is visible, reads thread_count from processor_set_statistics, PROCESSOR_SET_LOAD_INFO, about once a second. It does not sum thread counts from the available process-table rows.
When it's high
Apps doing several things in parallel, or background work, may have many threads. Threads can be waiting, so a large count is not the same as high CPU usage.
What you can do
  • If your Mac feels slow or the count keeps growing, open Activity Monitor (in the Utilities folder inside Applications) and check which apps use the most CPU or memory. Choose View > Columns to select columns, or select a process to inspect its information.
  • Quit apps you aren't using (save your work first). If an app doesn't respond, choose Apple menu > Force Quit, or click the Stop button in Activity Monitor and choose Force Quit. Force quitting can lose unsaved changes. Don't quit processes you don't recognize or processes that belong to macOS: if other apps or processes are using a process you quit, they can have problems (Apple). To see how processes are related, choose View > All Processes, Hierarchically in Activity Monitor.
Note
This is not the CPU core count, the run queue length or a total since startup. It includes kernel_task, so it may differ from a process-table sum or Activity Monitor readings taken at another time.

Nominal CPU frequency (P/E cluster maximum)

ID: cpu.frequency.nominal Nominal CPU frequency (cluster maximum)

Meaning
A nominal frequency describing the CPU's configuration. On Apple silicon, each P-core or E-core cluster shows a nominal (maximum) value. It is neither current frequency nor current CPU usage.
Unit
Raw values use Hz (cycles per second). The CPU page displays GHz (one billion Hz).
How it's measured
Read when CPU sampling is first needed, retaining successful values and confirmed missing sources or keys and incompatible tables. Only a failure to start enumeration or an invalidated enumeration is retried next time. On Apple silicon, it is the maximum in the pmgr voltage/frequency table in IORegistry: voltage-states5-sram for P, voltage-states1-sram for E. Intel retains the existing sysctl hw.cpufrequency as its nominal value.
When it's high
A higher frequency is recorded in the configuration table. It does not mean the CPU is running at that frequency now or that CPU load is high. This value alone cannot establish relative Mac performance or a hardware problem.
What you can do
  • There is no need to reduce this configuration value. If your Mac feels slow, open Activity Monitor (in the Utilities folder inside Applications) and use the CPU tab to find apps using the most CPU.
  • Quit apps you aren't using (save your work first). If an app doesn't respond, choose Apple menu > Force Quit, or click the Stop button in Activity Monitor and choose Force Quit. Force quitting can lose unsaved changes. Don't quit processes you don't recognize or processes that belong to macOS: if other apps or processes are using a process you quit, they can have problems (Apple). To see how processes are related, choose View > All Processes, Hierarchically in Activity Monitor.
Note
The Apple silicon value is an observation read from undocumented IORegistry keys, not a specification published by Apple. Tested on M1 only; M2 and later and Intel are unverified. Only Hz values with a maximum of at least 500 MHz are accepted. The kHz format on M4 and later is unverified on hardware: it is rejected as out of range rather than converted. M4 units and tables still need hardware comparison. A completed scan without pmgr or the required keys, or an incompatible table length or value range, is unsupported. These results are retained without rereading every second or substituting zero or another cluster's value. A failure to start enumeration or an invalidated enumeration is unavailable and retried next time. Current frequency is a separate, unsupported metric.

Memory

Memory (RAM) holds the data apps are using right now. When it runs short, macOS compresses data that isn't in use or writes it out to storage (swap) to make room. Apple recommends judging whether you have enough memory from Memory Pressure in Activity Monitor. Having little free memory isn't a problem by itself.

OS memory pressure event

ID: mem.pressure.event OS memory pressure event

Meaning
The last state of the memory pressure signal that macOS sends to apps (normal, warning, critical) and when it arrived.
How it's measured
Receives Dispatch memory pressure events (DispatchSource.makeMemoryPressureSource). Events arrive only when the state changes, so it shows Unobserved until the first one.
When it's warning or critical
Physical memory is running short and macOS is asking apps to use less. It happens when many apps or tabs are open at once.
What you can do
  • Open Activity Monitor (in the Utilities folder inside Applications), click the Memory tab and sort by the Memory column to find the apps using the most memory. In a browser, close tabs you aren't using.
  • Quit apps you aren't using (save your work first). If an app doesn't respond, choose Apple menu > Force Quit, or click the Stop button in Activity Monitor and choose Force Quit. Force quitting can lose unsaved changes. Don't quit processes you don't recognize or processes that belong to macOS: if other apps or processes are using a process you quit, they can have problems (Apple). To see how processes are related, choose View > All Processes, Hierarchically in Activity Monitor.
  • The color of the Memory Pressure graph below the list means, according to Apple: green, your Mac is using its RAM efficiently; yellow, it might eventually need more RAM; red, it needs more RAM. If it stays red, use fewer apps at the same time. Apple's article “Check if your Mac needs more RAM in Activity Monitor” explains how to see whether your Mac's memory can be upgraded.
Note
It's measured differently from the Memory Pressure graph in Activity Monitor, so the two may not match.

Memory breakdown (free, active, inactive, wired, speculative)

ID: mem.vm.free Free · mem.vm.active Active · mem.vm.inactive Inactive · mem.vm.wired Wired · mem.vm.speculative Speculative

Meaning
How physical memory is being used. Free is memory not used for anything; Active was used recently; Inactive hasn't been used for a while (it can be reused when needed); Wired is required by the system and can't be given to others (Wired Memory in Activity Monitor); Speculative was read ahead in advance (included in Free).
Unit
Bytes (number of pages × actual page size)
How it's measured
Converts the page counts from host_statistics64 (HOST_VM_INFO64) to bytes with the actual page size.
When free is low
That's normal. macOS uses spare memory for things like file caches. Judge whether memory is enough from the OS memory pressure event and Memory Pressure in Activity Monitor.
When wired is large
It's memory the system needs to operate. If memory pressure is also high, quit apps you aren't using, and restart your Mac if it doesn't come down.
Note
The parts don't add up to the total, because the categories overlap.

Cached Files

ID: mem.derived.cachedFiles Cached Files

Meaning
An indication of memory holding data such as file contents to speed up later reads, which can be reused when needed. It includes purgeable memory.
Unit
Bytes (GB on screen uses powers of 1024)
How it's measured
An app-derived value: (external_page_count + purgeable_count) × actual page size from one host_statistics64 (HOST_VM_INFO64) observation.
When it's high
It can rise after file reads. macOS normally uses spare memory for caches, so a large value alone doesn't indicate a problem.
What you can do
  • You don't need to clear it just to reduce the value.
  • If your Mac feels slow, also check Memory Pressure and swap in Activity Monitor (in the Utilities folder inside Applications).
Note
It overlaps with Reclaimable Memory and the raw classifications; don't add these values together. Missing fields mean Unsupported. When comparing with Activity Monitor, allow for differences in definitions, rounding and observation times.

Processes

Process CPU usage (one core)

ID: proc.cpu.usage Process CPU usage (one core)

Meaning
How much CPU the process is using. One fully used core is 100%, so a process using several cores goes above 100%.
Unit
% (one core = 100%)
How it's measured
The difference in the process's CPU time (PROC_PIDTASKINFO) divided by the elapsed time of a clock that stops during sleep. The interval is at least 250 milliseconds.
When it's high
The app is doing heavy work. If it stays high when the work should be done, the app may be unresponsive or repeating the same work.
What you can do
  • If it's working, let it finish.
  • Quit apps you aren't using (save your work first). If an app doesn't respond, choose Apple menu > Force Quit, or click the Stop button in Activity Monitor and choose Force Quit. Force quitting can lose unsaved changes. Don't quit processes you don't recognize or processes that belong to macOS: if other apps or processes are using a process you quit, they can have problems (Apple). To see how processes are related, choose View > All Processes, Hierarchically in Activity Monitor.
  • If it keeps happening, check for updates to the app (Apple's article “If an app freezes or quits unexpectedly on Mac”).
